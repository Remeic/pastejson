# Earlier landing paint and less scroll work

The landing heading paints earlier. Small scrolls retain the rows that stay visible. The JSON model and the lazy Search, Tree, Min, and Diff boundaries stay in place.

## Conditions

Baseline: `a482a95a987bac103b017cc95b83ab306ca4f733`, the head of PR #38. Test date: 2026-10-04 in Europe/Rome. Raw timestamps use UTC. Machine: Apple M4, macOS kernel 25.5.0. Engines: Bun 1.3.14 and Chrome 153.0.8010.53.

Both builds use the same installed dependencies. Each comparison has three warmup pairs and 21 measured pairs, in alternating AB/BA order. Tables show medians. HTML SHA256:

- Before: `6dbcbb8517a849dc876984fc06780717aefbf920c8b8ea431d3091b5c5519f32`.
- After: `f3124e36f3c1149fb88becabd2dcb9ed341fa7a5131894ca6fc4991b1ead43a7`.

Load tests use a loopback server, cache disabled, Service Worker bypassed, 100 ms network latency, 200,000 bytes/s download, and 4× main-page CPU throttling. They are cache-disabled navigations in one isolated Chrome process, not cold-process startup measurements. The server compresses HTML with Bun's `node:zlib`: gzip level 9 or Brotli quality 11.

All 63 candidate loads, including the gzip repeat, have zero CLS. One gzip baseline load has CLS 0.00128; it remains in the raw data. An earlier candidate without the visibility guard shifted by up to 0.00339 and was rejected. The benchmark rejects any candidate shift; it records baseline faults without discarding them.

## Cached loading

The existing production CSP allowed Blob workers but blocked the site's own `/sw.js`. The policy now also allows same-origin workers. Enabling the cache exposed a response regression: a Markdown fetch received cached HTML. The Service Worker now handles page navigation only, so other requests retain server content negotiation.

The cache comparison uses the real before/after policies, separate loopback origins, the same CPU/network limits, HTTP cache disabled, and Service Worker handling enabled. It has three warmup pairs and 11 alternating AB/BA pairs. Small HTML comments mark cache versions; the data records both original build hashes and served HTML hashes.

| Repeat navigation, median ms | Before | After |
| --- | ---: | ---: |
| Heading paint | 256 | 68 |
| DOMContentLoaded complete | 247.0 | 50.3 |

Heading paint falls **73.4%** on cached repeat visits. Installation fetches the shell once; cached visits refresh it in the background. The checks require a fresh version on the next navigation after that update, exact Markdown responses, offline shell loading, and exact 300 KB input through the Blob Worker while offline. All pass with zero candidate CSP violations and runtime exceptions. The cache stores the application shell, not pasted JSON.

## Responsiveness

The fixture contains 50,000 records and 4,698,378 input characters. Each sample performs 60 Text scroll steps: 30 down and 30 up, at 20 px per step. Every rendered row is checked against native pretty JSON, and the requested scroll offset must remain exact.

| Median work per step | gzip before | gzip after | Brotli before | Brotli after |
| --- | ---: | ---: | ---: | ---: |
| Script, ms | 0.3723 | 0.0439 | 0.3280 | 0.0632 |
| Layout, ms | 0.8123 | 0.0562 | 0.7945 | 0.0797 |
| Retained rows | 0 | 53 | 0 | 53 |

The gzip repeat measures script time of 0.3873 → 0.0825 ms and layout time of 0.8212 → 0.1265 ms per step. Across all three runs, script work falls **79–88%** and layout work falls **85–93%**. These CDP durations include the verification code. They are not INP or physical display latency. The gain applies to small scroll steps; large jumps and explicit state changes still replace the whole window.

Paste, search, case toggle, Tree, and Min were measured too. No separate gain is claimed. Their samples remain in the data. An identical-code calibration moved first-search handler time from 17.1 to 18.8 ms; small context differences alone do not establish a regression or an improvement.

## Stability and validation

Fast Tree → Text → New actions exposed two queued-paint exceptions in the baseline. Destroy now cancels the scheduled animation frame. The candidate has zero exceptions in the view comparison and performance runs.

- Nine delayed-module input cases preserve exact source, including invalid JSON, whitespace, file drop, latest-input selection, and a 1.1-million-character paste. Temporary listeners are removed. These cases bypass Service Worker responses so every navigation exercises the delayed module.
- Eleven browser scroll checks cover retained node identity, forced repaint, same-count state changes, resize, large jumps, empty documents, multi-element fallback, disposal, and the last of 600,000 compressed rows.
- Twenty-seven built-app windows are byte equal across Text, Search, Tree, Min, Diff, and side-by-side Diff. Footer hit targets and scalar status also pass.
- Desktop and mobile landing screenshots match the baseline pixels in both themes.
- Production build, 70 unit tests, 14 site checks, and 510 fuzz documents pass. The final paste gate reports 19.1 ms minimum pipeline time and walk/native 0.50, below the 0.75 limit. This is a gate result, not a paste speed claim. Source-state and search-navigation checks also pass. The delayed-module tests use the production CSP and require zero violations. Legacy virtual-time DOM runs are not used as proof; direct CDP checks cover the footer and scalar status.

Validation runs use a temporary source copy because Bun reads from the Documents folder can stall on this Mac. Production source and test files match the workspace byte for byte. Firefox startup failed in the local environment; no Firefox or Safari result is claimed. No ranking against other viewers is established.

Rejected changes: disabling identifier minification did not improve loading; deferring the lowercase search fold moved cost to a later case toggle; a search writer rewrite did not improve time. Removing critical layout CSS changed the UI and was rejected. Only CSS minification was retained.
